## 結論

個人図鑑・3列カード・カテゴリー／名前検索・新カテゴリー・写真プレビューは、ローカル実装と回帰検証を完了。投稿管理はマイページへ分離したが、現在は「投稿管理は準備中」と表示し、編集・公開取り下げは無効。

**旧履歴の発見者UIDが不明なため、公開直後に個人図鑑の表示件数が減ったり空になったりする可能性が残る。履歴の削除ではないが、この点を了承せずに一般公開へ切り替えるべきではない。** 本人のiPhoneに保存されている実際の旧履歴件数は、PCから取得できていない。

## 1. 過去の記録の保全

| 対象 | 今回の扱い |
|---|---|
| 既存EXP・冒険回数 | 保存キー・報酬計算を変更しない。起動・再読み込みを経ても既存値が変わらないテストを追加 |
| レベル | 既存EXPからの計算を変更しない。レベルの移行・初期化は追加しない |
| 進行中／完了冒険の原票 | 既存保存形式を維持。新規開始分の発見者UID以外は変更せず、起動・図鑑表示で消さない |
| 旧形式の発見履歴 | 元キーを維持し、自動でUIDに帰属させない。読み取りだけでは書き込まない |
| 新形式の個人図鑑 | UID別の別キーに保存。他UIDの図鑑を読み込んだり上書きしたりしない |
| 共有宝物・原本写真 | 今回は本番に一切書き込まない。個人図鑑化のための削除・非公開化をしない |

旧履歴保存を補強した。通常の正規到着で新しい登録宝物を追記する際、保存直前の旧履歴を読み直し、既存の全行・初回発見日・追加メタ情報を残して新しいIDだけを追加する。古い画面状態で、他タブが既に追加した履歴を落とさない。重複行を勝手に整理することもしない。

最初の変更前には `machiLegacyDiscoveryBackup.v1` へ旧JSONの原文を保全する。既に保全コピーがある場合は上書きしない。読み取り・検証・保全コピー作成が失敗した場合は旧履歴への書き込みを止め、元データを維持する。新図鑑・到着報酬は別処理とし、旧履歴が読めない場合も正規到着とEXPが正常に完了することをテストした。

これは旧履歴の保全であり、ユーザーUIDへの移行ではない。EXP・レベルの再計算や報酬再付与はしない。

## 2. 新図鑑に表示されなくなる件数

図鑑とマイページに読み取り専用の旧履歴案内を追加した。

- 読み取れた旧宝物数：旧形式の有効なIDを重複除外した件数。
- 新図鑑に同じ宝物がまだない件数：上記から、現在のUIDの新図鑑に正規到着で追加済みの同一IDを除いた件数。
- 除外理由：旧発見者UIDを確認できないため、自動移行していない。
- 同じ宝物が新規到着で表示済みでも、旧発見日の帰属・移行は未完了と案内する。
- 不正な行・重複行がある場合はそれぞれ件数を表示し、元の行は削除しない。
- JSONや保存領域を読めない場合は「件数は確認できません」と表示する。0件とは表示しない。

テスト例：旧宝物2件のうち、新図鑑に同じ宝物が1件ある場合、未表示の旧宝物は1件と表示する。この例は架空データであり、本人のiPhoneの件数ではない。

**本人のiPhoneの実数は未確認。** PC・別ブラウザー・別originの件数をiPhoneの件数として扱わない。従来の共有図鑑に表示されていた宝物21件も、本人の発見済み21件とは数えない。共有の登録件数と本人の発見履歴は別の数字。

過去の一般OSM施設への訪問は、従来の図鑑用履歴に保存されていなかったため、その未保存分の件数や施設をEXP合計から推測しない。新仕様で開始した通常ガチャの正規到着分から記録する。

## 5. 旧履歴を安全に引き継ぐ案（未実装・未実施）

1. 本人の端末で旧履歴の実数・読み取り状態を確認する。認証トークンを含むlocalStorage全体の出力はしない。
2. 旧履歴、新図鑑、EXP・冒険回数、残っている到着原票の必要な項目を、端末内で個別にバックアップする。公開リポジトリへ含めない。

4. 確認できた記録だけ、元ID・初回発見日・旧形式から移行した由来を保持してUID別へ結び付ける。同じ宝物が新図鑑にある場合も、内容を無断で置き換えない。
5. 移行ではGPS到着処理・EXP・冒険回数・発見人数更新RPCを再実行しない。
6. 移行後の件数・重複・日付を確認し、失敗時は移行先のバックアップへ戻す。旧履歴・原本写真は削除しない。

## 6. 残るリスク・公開前の確認点

- 旧履歴を未移行のまま公開すると、本人が以前見ていた図鑑より件数が減る／空になる可能性がある。件数と説明を見て判断する必要がある。
- iPhone実機での旧件数・新図鑑表示・再起動・アカウント切り替えは未検証。今回はPCの自動検証であり、実機成功とは扱わない。
- ブラウザー保存なので、サイトデータ削除や別端末への変更で記録が自動復元される保証はない。保存領域不足なら元データを優先して書き込みを止める。
- 完了冒険の原票は従来どおり次の冒険などで置き換わる。そこだけに残る未保存の過去訪問を永久に復旧できるわけではない。
- 同時に複数タブが書き込む場合の完全なトランザクションや、端末改変に対するサーバー検証は今回追加していない。
- 本番の既存宝物21件・原本写真27件への移行、削除、所有者の推測割り当ては一切実施していない。
