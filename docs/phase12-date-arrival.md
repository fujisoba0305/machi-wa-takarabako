# 第12工程：デートコースのGPS到着判定

2026-10-13。ローカル修正・検証のみ。DB/SQL/RLS、commit/push/デプロイ、有料APIの実通信は行っていない。

## 確認した原因

App.tsxの旧デート到着処理は、経由地でcourseStepを3に変更し、最終地点で直接50EXPと冒険回数を加算していた。どちらもGPS検証がなく、地図を開いた事実とボタン操作だけで進めた。通常ガチャのAdventureSessionは新しいGPS、100m、accuracy 50mで検証するが、デートの分岐には適用されていなかった。デート進行はReact stateだけで保存されていなかった。

## 新しい流れ

1. 検索結果から「経由地まで地図を開く」を押す。
2. 新しい出発GPSを取得し、精度を確認。冒険記録を保存してからGoogleマップの徒歩案内を開く。
3. Safariへ戻り「経由地に到着した」を押す。新しいGPSで固定保存した経由地の100m以内、accuracy 50m以内を確認。
4. 検証成功した経由地のGPSだけを保存。ここでは報酬なし。
5. 最終地点への徒歩案内を開き、戻って「ゴールした」を押す。
6. 経由地が検証済みであることと、最終地点の100m以内・accuracy 50m以内を新しいGPSで確認する。
7. 最終到着と報酬確定記録を先に保存し、50EXP・冒険回数+1を反映する。

同じ経由地のナビ押し直しでは冒険ID、出発位置、開始時刻は変更しない。「全体の地図を開く」は閲覧用のままで、冒険開始や到着の証拠にはしない。

## 保存・GPS・エラー

新しいlocalStorageキー `machiTakarabakoDateAdventure` を使用。既存の通常冒険キーの形式は変更しない。保存内容はversion、冒険ID、出発位置/accuracy/GPS時刻、開始時刻、2地点の固定ID/座標、表示用スポット/選択条件/冒険者名/既存距離、検証済み経由地GPS、最終GPS/完了時刻/報酬状態、報酬確定後のEXP・回数の総数。

GPS取得は通常冒険のrequestAdventurePositionを再利用する。maximumAge=0、enableHighAccuracy=true、timeout=10秒。30秒超の古い位置・不正座標等も通常と同様に拒否。距離は同じHaversine計算でkmからmに変換する。精度を到着半径に加算しない。

拒否・取得失敗・タイムアウトでは位置情報許可の確認と再試行を案内。精度不足では少し待って再試行を案内。範囲外では対象地点までの概算直線距離をmで表示。徒歩距離として表示しない。失敗では検証済み進行と報酬を増やさず、ボタンを再び利用できる。

GPS確認中はボタンを無効化し、セッション内部にも同期的な処理中ガードを置く。画面移動、新検索、アンマウントで古いGPS操作を無効化。保存済み冒険IDと進行をGPS取得後に再確認する。

再読み込みは保存済みGPSの座標・精度と対象地点の一致を再検証して復元する。地図を開いた段階は到着証拠として保存しない。経由地未確認なら経由地確認へ、経由地確認済みなら最終地点への案内へ戻る。宝物登録からの復帰も同じ記録を使用する。旧版で開始した未保存のデートは復元できず、更新後に新しく開始する必要がある。

## 報酬保存と限界

既存のEXP・回数はlocalStorageのmachiTakarabakoExp/machiTakarabakoAdventureCountに保存されており、デートの50EXPにサーバー側の到着検証や報酬台帳はない。

新しいデートでは最終到着を保存する際に、加算後の総EXP・回数を一緒に確定記録へ保存する。2つの既存カウンターを別々に書く途中で中断しても、再確認・再読み込み時に確定総数を再適用できる。差分50を繰り返し足さず、後で得たEXPも下げない。保存未完了の確定記録は新検索開始時にも復旧し、復旧できない間は破棄しない。完了画面・復帰・アニメーションの表示には加算処理がない。

localStorageは複数キーを原子的に更新できないため、この確定記録で中断からの復旧を補っている。通常の二重タップ、リロード、保存済み完了を別セッションから確認する操作をテスト済み。ただしブラウザーの記録改ざん、GPS偽装、複数端末からの同時操作に対する完全な不正防止ではない。通常宝物の発見RPCもクライアントから施設IDを渡す構成であり、実DBのサーバー実装は今回変更・監査していない。

今回は最低歩行時間・速度・出発地点からの移動量を追加していない。最初から対象地点の100m以内に実際にいる場合は既存の距離条件を満たす。広い公園などの代表点と入口のずれも今回のGPS閾値変更では解決していない。

## iPhone Safariで確認してほしい操作

1. これまで使用しているローカルHTTPS URLを開き、ページを再読み込みする。保存データやサイトデータは削除しない。本番にはまだ反映していない。
2. 新しく食べ歩きデートを検索し、経由地の案内を開く。Safariへ戻り、対象地点から100mより遠い場所で到着を押す。残り距離が表示され、最終案内・50EXPが出ないことを確認する。
3. 位置情報を拒否した場合、到着できず案内が出ることを確認。許可を戻して再試行する。端末設定の「正確な位置情報」も確認する。
4. 経由地の近くまで歩き、到着確認する。経由地到着後もEXPが増えていないことを確認。
5. 最終案内を開き、まだ最終地点から遠いままゴールを押す。完了しないことを確認。最終地点付近に移動して再確認し、50EXPと冒険回数1だけ増えることを確認する。
6. 途中でSafariを再読み込み、ホームへ移動して「冒険の続きに戻る」、宝物登録から戻る操作を行う。目的地と検証済み進行が維持されることを確認する。
7. 完了後の再読み込みや連打でEXPが増えないことを確認する。他のデートモードと通常ガチャも1回ずつ確認する。

GPS精度が50mを超える場合は、空が見える安全な場所で少し待って再試行する。検証のために危険な場所や立入禁止区域へ入らない。
