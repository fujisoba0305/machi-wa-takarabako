## 実装

- 既存56,701施設を一字も変更せず、新5県の32,247施設を追加。合計88,948施設。
- 新データは0.1度の378区画。区画は都県に分断せず、検索円の外接範囲に重なる隣接区画をすべて取得する。最終候補は従来の球面直線距離で絞る。道路探索を復活させない。
- 東京・神奈川で検索円全体が旧収録範囲内なら、従来の2ファイルの読み込みを維持。境界からの安全余裕を確認できなければ新区画方式に切り替える。県境付近では候補が増える場合がある。
- 新区画は同時取得3件、同一区画の取得を共有。保持キャッシュは48区画かつJSONバイト見積24MiBまで。これはブラウザー全体のメモリ上限ではない。
- 必須区画の取得・検証に失敗したら部分結果を返さず失敗とし、同じ条件で再試行できる。正常0件とは区別する。SHA-256検証、形式検証、OSM IDとcanonical IDによる重複排除を維持。
- 同名の公園nodeが実際の公園wayポリゴン内にある場合のみ同一候補として扱う。名称や近さだけでは別施設を統合しない。
- 「？km」とデートの既存静的検索入口も7都県に拡張。今回の24地点では各候補検索168条件・144条件ともOverpassへ進まず処理できた。ただし0件はそれぞれ7条件・9条件。デートの現地適性や全コース成立を保証するものではない。
- GPS、認証、EXP、育成、投稿、Supabase取得、登録宝物50%分岐、倍率1.1435、65%上限、各距離範囲、タイムアウトは変更していない。

## 再生成・切り戻し

Node24、外部作業用のosm-pbf-parserと@turf/boolean-point-in-polygonを使用。アプリ実行時の依存追加なし。

1. OSM_TOOLS_ROOTを上記2ライブラリのある作業用package.jsonのディレクトリに設定。
2. node scripts-extract-kanto-facilities.cjs --pbf <原本> --out <作業用ディレクトリ>
3. node scripts-build-kanto-facilities.mjs --raw <作業用/candidates-raw.json> --coverage <作業用/coverage.json> --report <作業用/generation.json>
4. マニフェストのsource.snapshotUTC・versionを原本と必ず照合（今回の生成スクリプトは今回のスナップショット情報を持つ）。新スナップショットでは更新する。
5. 新しいハッシュ名の区画、マニフェスト、テストをまとめて検証。古いデータを自動削除する仕組みは設けない。

VITE_KANTO_STATIC_SEARCH=offで今回の7都県拡張のみを無効にして従来東京・神奈川へ戻せる（ビルド時設定）。GPS・ユーザー保存データは変更しない。今は環境変数変更も行っていない。
