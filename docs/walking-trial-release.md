# 徒歩検索・試験版：第26工程の公開前確認

## 実装範囲
今井南町の公開町代表点を中心とする既存半径12km道路データを、本人限定の固定距離ガチャへ接続。東京・神奈川全域対応ではない。
通常検索のコードは残し、試験版は初期OFF。ログイン後、許可対象だけに切替チェックを表示する。URLパラメータ、利用者が編集できるプロフィール、JWTの未検証payloadでは許可しない。
「？km」とデートの経路は変更しない。

## 権限設定（公開承認後のみ）
VercelのProduction環境にサーバー専用変数を設定する。
- WALKING_TRIAL_ENABLED: on
- WALKING_TRIAL_USER_IDS: ユーザーから指定された本人のSupabase User UID（VITE_を付けない。実UIDをリポジトリに書かない）
- SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY、または既存の VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY をサーバー側で利用。
Client Secret、service_roleキー、Google APIキーの追加は不要。
値未設定・無効設定・認証失敗は許可しない。設定変更後に承認されたデプロイへ反映する。

権限APIはログインのBearerトークンをSupabase Authの/auth/v1/userで検証し、信頼できるUser IDを許可リストと照合する。処理の前後に再確認し、結果表示前のログアウト・無効化を反映。トークンやUIDを応答/診断へ出さない。
根拠：[Supabase公式 getUser](https://supabase.com/docs/reference/javascript/auth-getuser)。DB・SQL・RLSは使わず、認証の読み取りのみ。
利用者のブラウザー内計算であり、公開OSMデータや計算コードそのものを秘密情報として保護する設計ではない。既存のクライアントGPS報酬処理を不正取得完全防止とは扱わない。

## 無料検索と配信
有料API・公開Overpass・外部ルーティングAPIへの経路を追加しない。試験版の検索と冒険開始はGoogle Routesを呼ばない。Googleマップへの通常徒歩リンクは維持。
879個の必要な公開データだけをgzipで配信し、全元データSHA-256との一致を検証。合計180,473,105 bytes（180.47MB）。生データ・バックアップ・秘密鍵・証明書・.env・ユーザーのGPS・投稿写真はpublicへ入れていない。
Vercel標準静的ファイルとWeb Worker、DecompressionStream('gzip')を使用。古いSafari等で展開不可なら明確に停止し、有料APIへ移行しない。HTTPS本番URLだけで動き、LANサーバーに依存しない。
地域分割と一括への容量判断フォールバックを維持。原データと元のOSM点IDを保持し、地域境界で道路を切らない。
1km初回配信見込み5.39MB、3km7.44MB、5/10km11.70MB（新しいWorker・町代表地点のgzip）。LAN試作のBrotliより大きい。実際のVercel転送量・iPhone所要時間は未確認。
転送量は既存Vercelプランの使用量へ加算される。API追加課金はないが、ホスティング枠の無制限無料運用を保証しない。現在のプラン/残枠は未監査。静的キャッシュを設定し、同じタブではデータ・探索を再利用。
ODbL帰属と加工データの取得方法は /walking-trial/LICENSE.md に掲載。公開OSMデータは認証なしで取得可能。

## 距離・到達性
1km=0〜2km、3km=2〜4km、5km=4〜6km、10km=9〜11km。道路網上の探索と、根拠がある施設接続の推定区間に基づく従来試作の判定を維持。直線距離を徒歩距離として代用しない。
料理ジャンル・おまかせ分岐は本体のresolveStaticConditionで確定しWorkerへ渡す。
OSM施設ID・登録座標を本体Spotへ変換。距離は「推定徒歩距離（道路網部分）」、ウォーキング/到着記録では「検索時」と表示。出発時実測や入口までの到達確認として扱わない。
登録宝物はカテゴリ/料理不明の規則を維持。直線距離は上限の粗い事前除外だけで、徒歩合格には使わない。道路への接続根拠と徒歩距離を確認できた候補だけ50%分岐へ渡す。接続不明の宝物は試験版の固定距離候補から保留し、データ自体は変更しない。
起点unknown・建物内などの保留は解除しない。街区外周の到達を施設到達にしない。

## 冒険と保存
到着は登録目的地座標から100m以内・GPS精度50m以内の既存処理のまま。推定距離を到着条件へ渡さない。
通常20EXP、宝物30EXP、冒険回数、発見、評価、二重取得防止は既存処理。ゲスト記録や認証ストレージの削除/移行なし。
既存version1の冒険記録に任意の result.walkingTrial を追加。旧記録はそのまま読み込める。新記録も目標座標と報酬条件は同一。測定報告に位置・施設名・トークンを含めない。
GPS再取得、通信障害、候補0件、未対応地域、範囲不足を区別。古い結果を破棄し、待機上限・中止・同条件再試行を使用。検索障害時に通常APIへ自動切替しない。

## ロールバック
1. 本人がチェックを外す：次の固定距離検索から既存方式へ戻る。進行中の冒険は既存GPS条件で継続できる。
2. 全体停止：WALKING_TRIAL_ENABLED を off にし、承認されたデプロイで反映。権限APIが拒否するため古いタブでも新検索・検索結果確定を拒否。
3. コード全体の切り戻し：Vercelの直前正常Production Deployment B3rm19TK4y1Y2sL8WNFTApPaBQx5、commit 47559c6722f03dc860c4e300f3bc09998943387d へ戻す。DBとlocalStorageを削除しない。
旧版は新しい任意フィールドを無視して既存目標とGPS判定を使用できる。旧版で再開時の距離表示は取得なしとなる場合があるが、報酬や目標は変わらない。
