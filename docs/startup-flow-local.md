# 初回登録・次回起動フローのローカル改善

2026-10-16。基点commitは82f2b61764c8e7c865ae9180f282d60e7c5fbc13。commit・push・デプロイ・DB変更・認証設定変更は行っていない。

## 調査結果

既存のSupabase AuthはmachiAccountAuth.v1にPKCEセッションを保持し、自動更新に対応している。Googleのfull_nameは表示用で、任意の冒険者名の永続保存は存在しなかった。旧Appでは冒険中・直近冒険のplayerNameだけを復元し、それ以外の起動では名前が空になっていた。

初回の名前フォームはGPS結果を待たずホームへ進んでいた。通常の検索用GPSは精度・取得日時を保持せず、取得から最大5分まで再利用していた。冒険復帰時の出発座標もcurrentLocationへ初期設定されていた。これらは今回修正した。到着判定そのもの（登録座標から100m以内・accuracy50m以内）は変更していない。

## 実装した流れ

- タイトルからGoogleログインを選び、戻った後に冒険者名と位置情報の説明・許可へ進む。Googleログイン完了までGPSを取得しない。既存のゲスト記録は削除せず保持する。
- 同じブラウザに完了済みプロフィールがあり有効なログインを復元できれば、名前入力・再ログイン・起動時GPSを省いて開始する。未ログインの起動では、保存名があってもGoogleログインを待つ。
- 新規キーmachiAdventurerProfiles.v1に、guestとuser:UIDを分けて名前と登録完了状態だけを保存。既存EXP・冒険・写真・発見・評価キーは削除・移行しない。
- 旧冒険の名前はゲスト名として保全する。Googleユーザーへコピー・候補表示しない。旧形式には所有UIDがないため、旧形式のみの利用者はログイン後に一度名前を入力する。以降はUID別の保存名を復元する。この扱いは2026-10-16にユーザー承認済み。記録やEXPのクラウド移行ではない。
- マイページで冒険者名を変更可能。ログアウト後の再ログインでアカウント選択可能。冒険中のアカウント操作・名前編集は既存冒険を守るため制限する。
- アカウント切替では試験版をOFFにし、古い検索起点を無効化する。進行中の冒険データは残す。

## GPS対策

新規登録、通常検索の現在地取得、試験検索の事前GPSに、maximumAge:0・高精度・10秒タイムアウトを利用する。取得日時が30秒超、未来5秒超、不正座標などは拒否する。Safariでコールバックが来ない場合も12秒で操作を戻す。権限拒否・取得不能・時間切れ・古い位置を別々に案内し、再試行可能とする。

登録のGPSに失敗した場合は名前を下書きとして保持し、ホームへ進まず再試行できる。通常検索は30秒より古い位置や復帰時の出発点を現在地として使わない。試験検索のaccuracy50m条件は維持。到着時GPS・EXP・二重報酬防止は既存処理を維持する。

この登録処理では位置情報をサーバーにも新しいプロフィール保存キーにも書き込まない。既存の宝物投稿や冒険記録など、用途がある既存位置データの保存仕様は変更していない。

## 起動負荷

タイトル背景PNGは3,878,809 bytes（約3.9MB）。登録済み起動で背景を不要に取得しないよう、登録が必要と分かるまで背景URLを適用しない。初回登録が必要な場合の画像そのものは変更しておらず、この約3.9MBは残る。JSの圧縮後は従来約202KBから約205KBに増加。iPhoneでの秒数改善を実測したわけではない。

徒歩検索初回の道路取得は起動画像とは別の負荷。今回、道路データ・Worker・距離条件は変更していない。過去のiPhoneエラーの実際のerror.codeや発生時ログがないため、個別端末の原因を確定したとは扱わない。
