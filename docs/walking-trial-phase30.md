# 第30工程：本人限定・1km徒歩検索の公開前報告

ローカル統合と自動検証は完了。**commit・push・本番公開・本番の環境変数変更は未実施**。指定済み本人UIDはコード・公開データ・この報告書に埋め込んでいない。

## 初期設定

- アプリ起動時の試験スイッチはOFF。許可された本人がGoogleログインした時だけ切替を表示する。
- 初期の試験対象は1km（道路距離0〜2km）のみ。
- 3km（2〜4km）は実装・PCテスト済みだが、サーバー専用の `WALKING_TRIAL_3KM_ENABLED` が `on` でない限り無効。初回公開では `off` にする。
- 3km無効時の3km、および5km・10km・？km・デートは既存経路を維持する。
- OFF操作で次の検索は従来経路へ戻る。検索中にも中止・OFFボタンが使える。画面の再読み込みでもOFFへ戻る。

## 権限と保護

権限APIはSupabase Authの `/auth/v1/user` でトークンを検証し、サーバーの許可UIDと照合する。URLパラメータ、編集可能なプロフィール、未検証JWTだけでは許可しない。検索前後にも再確認する。ゲスト、別UID、匿名認証、失効、認証通信エラーは許可しない。未許可時は試験欄自体を表示しない。

本人限定なのは本体の試験機能へのアクセス。OSMデータとブラウザー用計算コードは公開であり、秘密データではない。クライアントのGPS・報酬処理を、不正取得の完全防止とは扱わない。

Googleログイン、登録宝物、図鑑、写真、評価、EXP・冒険回数の保存処理は変更していない。DB・SQL・RLSも変更していない。第26工程の未コミットの本体側接続は保全し、今回の全域版へ更新した。古い独立試作・一括データ・旧地域データも削除していない。

## データと距離

既存56,701施設、道路区画、条件別施設プロフィール、起点周辺の接続根拠を利用。必要な道路区画と条件だけを取得し、全域一括取得へ自動移行しない。東京・神奈川の既存の検証済み境界も再利用する。対象外、道路不足、通信障害、候補0件を分け、勝手な条件変更や旧APIへの自動退避はしない。

道路距離はOSM道路網上の探索で計算する。直線距離を徒歩距離として扱わない。街区外周までの推定を施設入口までの正確な距離と表示しない。起点unknown、街区推定、現地未確認を維持する。起点unknownの場合、現在地からの総徒歩距離も未確認。

登録宝物は従来のカテゴリ・料理条件で絞り、同じ道路網による接続根拠と徒歩距離を確認できたものだけを抽選へ渡す。接続不明は保留。一般施設と登録宝物が両方ある場合の50%分岐は維持する。一般施設も全候補から抽選し、画面へは選択候補・件数だけを返して大量複製を避ける。

到着判定は**元の目的地GPS座標から100m以内・精度50m以内**の既存処理。道路上の計算地点を到着点に置き換えていない。20/30EXP、発見・評価、二重報酬防止を維持し、推定距離を到着成功の根拠にしない。Googleマップへの通常の徒歩案内リンクも維持する。

未対応の既知6条件は、奥多摩10km、檜原3/5/10km、丹沢湖5/10km。これらを対応済みにはしていない。景色カテゴリの候補不足や、道路網の分離による0件も残る。

## iPhoneに備えた動作

- GPS確認、登録宝物、一覧、道路、施設、接続根拠、探索の進行状況を表示。
- 起動前の認証待ちを含めて中止でき、検索全体にも90秒の上限を設定。
- 中止・エラー・画面退避・Safariからの復帰でWorkerを破棄し、古い結果を反映しない。
- 同条件は再利用。条件変更3回、待機30秒でも保持データを解放する。
- 初回準備・検索・宝物接続確認・読込本文量・品質分類を測定表示する。コピーには座標・施設名・UID・トークンを含めない。
- Worker停止時は再試行の案内を出す。ただしOSがSafariのタブ全体を終了する場合、画面内復旧は保証できない。開き直すと試験スイッチはOFFになる。冒険・EXPの保存データを削除しない。

## 配信量と公開用パッケージ

全域の展開データは**15,043ファイル・702,566,618 bytes（約703MB）**。これはサーバーの保管量で、1回の検索で全部を取得する量ではない。

Gitには区画をまとめた23個の検証付きアーカイブ（合計704,452,071 bytes）を用意し、`predev/pretest/prebuild` でオフライン復元する。1ファイル最大は約32.62MB。`npm run verify:walking-data` で全23アーカイブと15,043要素のハッシュ・長さ・許可パスを検証済み。生成したpublicデータはGit対象外。現在の公開候補全体は216ソースファイル・約727MB。本番ビルド出力は15,070ファイル・約719MB。

古い地域限定publicデータはローカルに保全し、Git対象から除外した。ビルド終了時に、古い試験版の生成出力だけを除外する。元データを削除する処理ではない。現在のデータだけを版固定URLで配信する。データは長期キャッシュ、実行コードは再検証、manifestと権限応答はno-storeとし、版の混在を防ぐ。バイナリ配信のContent-Encodingはidentityとし、読込時のSHA-256検証も行う。

武蔵小杉の一般施設カフェを使うPC内HTTP・実際のビルド済みWorkerでは、1kmの本文取得約3.32MB・初回約0.72秒・再検索約14ms・39候補。再検索は0リクエスト・本文0 bytes。本人権限API・GPS・登録宝物の通信は含まない。フロント側の県境データを初取得する場合は圧縮約0.21MBが加わるため、一般施設だけの初回追加量目安は**約3.53MB＋アプリ本体・画像等**。登録宝物の接続根拠や地域・カテゴリにより増える。新宿の1kmは施設密度が高く、前工程では約4.97MB＋境界データだった。

3kmのHTTP測定は1km後の同Workerで約0.63秒・33候補。完全初回の3km性能やiPhoneの値として扱わない。今回の測定詳細は作業用 `phase30/http-results.json` に保存。

Vercel公式のHobby枠はFast Data Transfer 100GB、Fast Origin Transfer 10GB、CDN Requests 100万。例として3.53MBの完全初回検索100回は約0.353GBで、他の画像・アプリ・既存利用分は別。現在の実アカウントのプラン・消費量・残枠は未確認。APIを無料化しても配信・保管枠が無制限になるわけではない。

CLIのHobbyソースアップロード上限は100MBのため、この構成で手動CLIデプロイは行わない。承認後は既存のGit連携を使用し、ビルド・配信結果を確認する。元データの版更新を繰り返すとGit保管量も増える。今回、有料サービスの導入・プラン変更・課金設定は行っていない。
