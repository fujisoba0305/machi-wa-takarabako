# 徒歩試験版・約20秒の停止調査（ローカルのみ）

2026-10-16 JST。基点本番commit: 5c2e6ba11fdf7dedf567e6a1e43dbe7945440644。

## 今回の停止理由

ユーザーが確認した説明文「現在地と道路の間に障害物があり、安全な接続を確認できません」は、walkingTrial.ts がWorkerの status=origin-blocked を受け取った場合に表示する。この文言から、今回の停止段階はGPS起点と道路の接続判定と特定できる。20秒共通タイムアウトではない。

本番の処理では、新しいGPS取得と精度50m以内の確認、登録宝物取得、試験権限確認、道路・施設・起点の接続根拠の読み込みを経て、origin-blockedを返す。道路網の徒歩探索・目的地抽選へは進んでいない。施設の存在しない正常0件とは異なる。Workerが判定結果を返したため、この停止についてWorker起動失敗や致命的なメモリ停止を原因とは判断しない。iPhone全体のメモリ使用量は未計測。

## 未特定の部分

現行の本番画面は originConnection.reason（建物・水路・線路・壁・制限敷地など）を表示・測定結果へ保存していない。どの種類に抵触したか、実際の障害物か、GPSのずれか、OSM形状のずれかは未特定。正確なGPS座標を取得して原因を推測したものではない。

## 待機期限の監査

| 処理 | 期限 |
|---|---|
| GPS前のログイン確認 | 8秒 |
| ブラウザーGPS | 10秒、無応答監視12秒 |
| 登録宝物の取得 | 15秒 |
| 試験権限API | 10秒（サーバー側の認証照会は8秒） |
| manifestと地域情報 | 合計10秒 |
| Worker起動・計算の無応答 | 30秒。データ取得段階は90秒 |
| 試験エンジン全体 | 90秒 |
| 検索画面の予備監視 | 検索中でも成功でも失敗でもない場合だけ5秒 |
| デート専用処理 | 20秒。今回の1km・カフェ試験には適用されない |

単純な期限延長は実施していない。5秒のGPSと15秒の登録宝物待ちで合計20秒になる別経路は存在するが、今回の説明文とは異なるため今回の原因とは扱わない。

## PCの19.2秒との関係

phase30-production-results.json の初回は19,204.8ms、Worker 19,156.8ms、取得本文3,319,997 bytes、カフェ39候補、起点分類unknown。2回目は13.4ms、取得本文0 bytes。これは公開テスト座標から本番静的データを読むPCのWorker検証で、本人認証・GPS・登録宝物取得は含まない。今回のiPhoneはorigin-blockedであり、同じ結果ではない。約19.2秒は打ち切り設定ではなく、当時の測定値。iPhoneの20秒の内訳は未計測。

## ローカル修正

1. origin-blockedとorigin-unconnectedの結果に、停止段階・安全な理由分類・読み込み時間・Worker時間・取得本文量を付ける。生の座標・施設名・UID・トークン・OSM識別子は含めない。
2. GPSや登録宝物取得など、Worker前の失敗にも段階別診断を残す。失敗時は測定結果を開いた状態にする。既存のコピー機能で共有できる。
3. 起点接続を施設プロファイル取得より前に判定する。接続保留が分かった場合は不要な施設プロファイルを取得しない。道路データ・接続の基準・距離条件・到達判定は変更しない。

この修正は実機の接続保留を安全確認済みに変えるものではない。建物などの種類が分からないまま道路へ強制接続しない。

## 再検索

同じGPS点と道路・障害物データならキャッシュ後にもorigin-blockedは起こり得る。初回の通信だけの問題ではない。実データエンジンを使う模擬建物テストでは、同じ点は繰り返し保留し、入力点を根拠のある道路線上へ移した場合にだけ保留を解除する。これはPC内の模擬入力であり、iPhone実GPSテストではない。
